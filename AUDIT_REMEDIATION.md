# BraneWaves / BrainWeave Audit Remediation

This document records the full repository audit and the remediation applied on
`fix/full-audit-remediation`.

## Fixed

| Severity | Finding | Remediation |
|---|---|---|
| Critical | Next.js 15.1.3 / React 19.0 security exposure | Upgraded to Next.js 15.5.27 and React/React DOM 19.3.0; aligned eslint-config-next. |
| Critical | Untrusted Python executed as a local host subprocess | Removed local execution. The API now forwards code only to a separately isolated sandbox configured with `PYTHON_SANDBOX_URL`; otherwise code execution is disabled. |
| High | Docker queued tasks but had no worker service | Added the worker service to Docker Compose and made queued jobs recoverable through a processing list. |
| High | Report citations and report document used different IDs | A single report ID is generated by the orchestrator and passed through citation/report persistence. |
| High | Tool `permission_scope` was metadata only | Registry now enforces global allowlist, per-agent allowed tools, and permission scopes. |
| High | Refresh tokens stored in plaintext MongoDB sessions | Sessions now store SHA-256 token digests; legacy plaintext sessions/indexes are invalidated on startup. |
| High | Refresh tokens stored in browser localStorage and OAuth URL fragments | Refresh tokens now use HttpOnly cookies. OAuth exposes only a short-lived access token in the fragment. Legacy browser refresh-token storage is cleared. |
| High | Predictable/default JWT secret could reach production | Production startup now fails if the JWT secret is missing/weak/example. |
| High | Missing GROQ_API_KEY only logged a fatal message | Production startup fails closed when the key is missing. |
| High | Cost table used stale model pricing | Updated GPT-OSS 20B/120B and Qwen 3.8 pricing from current Groq docs. |
| High | Deprecated/preview models in production fallback chain | Production fallback chain now uses stable GPT-OSS 20B and 120B. |
| High | User usage quota was not enforced when creating tasks | Task budget is clamped to app limits and remaining account quota. |
| High | Task embedded budget did not include every LLM call | Cost is now incremented from the authoritative per-call usage recorder; report chat also updates task spend. |
| High | Planner could exceed configured max task steps | Orchestrator rejects plans that exceed the task step limit. |
| High | Production report could start after budget was already exhausted | Orchestrator checks task budget again before report generation. |
| High | Actual uploaded PDF/DOCX files were committed | Removed tracked upload artifacts from the remediation branch; uploads remain ignored by Git. |
| High | Knowledge-base delete left physical files on disk | Delete now removes Mongo metadata/chunks and the stored file. |
| High | MongoDB and Redis were published on host ports in Compose | Database/cache services now stay on the internal Compose network. |
| Medium | No production-oriented frontend/container stack | Added `frontend/Dockerfile.prod` and `docker-compose.prod.yml`. |
| Medium | RAG silently searched only the first 3000 chunks | Removed silent 3000-candidate truncation. README now documents that current FAISS indexing is in-process and a persistent vector service is recommended at scale. |
| Medium | Rate limiter failed open when Redis was unavailable | Added a per-process in-memory fallback limiter. |
| Medium | Prompt-injection regex was treated as a security boundary | Detection is now advisory telemetry; hard protections are tool authorization and isolated execution. |
| Medium | Report chat accepted effectively unbounded messages | Added a 4000-character request limit. |
| Medium | Citation verifier checked only one resolved IP | It now validates every currently resolved address and still refuses redirects/private/link-local/loopback/reserved targets. |
| Medium | README overstated sandbox/RAG/caching/security claims | README now reflects actual implementation and dev-vs-production Docker usage. |
| Medium | Environment template disagreed with application defaults | Aligned Groq URL, budgets, chunk sizes, and added sandbox settings. |
| Medium | No CI workflow | Added GitHub Actions backend tests and frontend production build. |
| Medium | Frontend OAuth URLs were hard-coded to localhost | Login page now uses `NEXT_PUBLIC_API_URL`. |
| Medium | Planner generated a report step and orchestrator generated another final report | Planner no longer creates report steps; the orchestrator owns a single final-report phase. |
| Medium | Worker container ran as root | Worker image now runs as a dedicated non-root user. |
| Medium | Production uploads were ephemeral | Production Compose now persists uploads in a named volume. |
| Medium | README advertised caching analytics/cost savings without a backing implementation | Unsupported cache claims were removed; analytics documentation now matches the implemented endpoint. |
| Medium | Auth session TTL was hard-coded to seven days | Session persistence now follows `JWT_REFRESH_TOKEN_EXPIRE_DAYS`. |
| Medium | Deactivated users could continue refreshing existing sessions | Refresh now checks that the user is active. |

## Git history purge status

The repository's reachable Git history has been rewritten to remove the tracked
PDF/DOCX upload artifacts:

- `main` was force-updated from the tainted history to clean replacement commits.
- `fix/full-audit-remediation` was re-anchored as a clean commit on top of the
  rewritten `main`.
- The open pull request head and merge refs now point to clean commits.
- The repository has no forks and no tag refs were present during the rewrite.
- `.gitignore` continues to prevent future tracked uploads under
  `backend/uploads/`.

GitHub still retains the old unreachable commit/tree objects by SHA immediately
after the rewrite. GitHub's documented sensitive-data removal process requires
GitHub Support to dereference cached pull-request views and run server-side
garbage collection for complete expungement. The first tainted commit identified
during this cleanup was:

`d53bcead20bcd6ed363c887dd423b8075dda1080`

Affected pull requests: **1**.

## Verification

The pull request for this branch runs:

- Python 3.11 + backend pytest suite with MongoDB and Redis services.
- Node 20 + frontend `npm install` and `npm run build`.

The repository's execution environment used for this audit could not directly
clone GitHub or reach npm, so GitHub Actions is the authoritative build/test
verification for these changes.
